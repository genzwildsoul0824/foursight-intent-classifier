FourSight intent classification

GitHub: https://github.com/genzwildsoul0824/foursight-intent-classifier  |  Hugging Face: https://huggingface.co/henhua21/foursight-intent-e5  |  W&B: https://wandb.ai/henhua21-tiktok/foursight-intent

1. Approach

What I saw in the data shaped the approach:

  • Imbalance. realtime 782 rows vs chitchat 17. Macro-F1 is 60% of the score, so the rare classes decide it.
  • Multilingual. Questions in seven or more languages.
  • Conversation order. Row IDs follow conversation order. Adjacent rows share a label 41% of the time, against 28% by chance, and many rows are follow-ups ("yes", "both", a bare load ID) that only make sense with the turn before.
  • Noisy labels. 79 rows share their exact text with a row that has a different label, mostly realtime vs shipment_information.

Model. I fine-tuned intfloat/multilingual-e5-base (an XLM-R model further trained for sentence similarity) with a 7-class head. Its input is the pair (current question, previous two questions).

  • Context dropout 0.5. During training, half the time the model sees the question alone, so it still works with no history.
  • Class weights. Balanced class weights make it learn the rare classes. This also makes it over-predict them.
  • Post-processing (calibration.json) fixes that:
    • one bias per class;
    • a transition prior on the previous turn's predicted intent;
    • a temperature that makes the confidences calibrated;
    • needs_review when the calibrated confidence is below 0.5.

Why not something else. Routing is closed-set, high-volume classification. An encoder with argmax is fast, runs on CPU, and is deterministic by construction. An LLM would need constrained decoding and still wouldn't know this dataset's labelling conventions.

I compared four alternatives on the same folds: TF-IDF + LR, frozen e5 + LR, mDeBERTa-v3 and XLM-R. With the same bias correction, fine-tuned e5 was best (68.7 vs 67.8 mDeBERTa vs 64.2 XLM-R, optimistic numbers used only to rank them) and the fastest.

Determinism.

  • Fixed seeds and torch.use_deterministic_algorithms. Inference is fp32 argmax.
  • Two prediction runs give byte-identical files. CPU and GPU give the same 566 labels. Predicting from the published Hugging Face model reproduces the submission exactly.

2. Validation results

Protocol. 5-fold stratified grouped CV. Groups are blocks of 20 consecutive IDs (sessions), and duplicate questions are pinned to one group: 0 duplicates cross folds, and 90% of neighbouring rows share a fold. A random split would leak duplicates and conversations into validation.

All post-processing is itself cross-validated (fit on 4 folds, applied to the 5th). Tuning on all out-of-fold predictions would have reported 69.5 instead of the honest 67.7.

Where it fails.

  • shipment_information vs realtime_query (138 + 72 errors). Part of this is the labels: 17 duplicated texts, including bare load IDs, carry both labels, so at least 37 rows are wrong for any model that reads only the question. The rest is real overlap between "where is it" and "what is its status".
  • analytics → realtime (62). These are questions about many loads that are phrased like a single-load lookup.
  • other (F1 20). A 55-example catch-all with no common theme, often confused with knowledge_base.
  • The rare classes now work (chitchat 81, disruptions 78), but they rest on 17 and 28 examples, so these numbers have wide uncertainty. Fold-to-fold spread is about ±3 OVERALL.

3. Conversational history

Built and measured. Two mechanisms, both validated on sessions recovered from ID order.

  • (a) Context in the encoder. The previous two questions go in as the second text of a pair. The question comes first, so truncation never cuts it.
    • With a linear model, adding context hurt; it only helped when gated to fragments. The fine-tuned encoder attends across both texts and learns when context matters. It helps full questions too, because labels are session-level.
    • Context dropout keeps it usable without history: 58.0 raw OVERALL with no context, where a model trained always with context collapses to 53.3.
  • (b) Transition prior. P(current intent | previous predicted intent) from a 7×7 table counted on training turns, added to the logits with strength α = 0.25 (chosen inside CV). It is cheap, deterministic and auditable. Together with (a) it lifts fragment accuracy from 61.8 to 66.0 and OVERALL by +1.1 over the no-context model.

Production design.

  • Session state. Keep per session: the last K turns (user questions and bot answers), the last routed intent, and extracted entities (load/PO IDs, date ranges, filters such as lane or carrier).
    • Context is taken only from the same session ID. Here, the missing session boundaries are the main source of context errors, e.g. a "hi" that opens a chat gets someone else's history.
    • The router gets (question, recent turns) as now, plus the last routed intent through the prior.
  • Follow-ups. "what about last month?" is routed with the previous intent and inherits its entities, with the date range overwritten, so the downstream product receives a complete query.
  • Optional rewriter. Later, a small constrained, greedy-decoding rewriter could turn follow-ups into standalone questions for the downstream products.
  • Labelling. Label logged conversations per turn, with the conversation visible to annotators, so labels become consistent. Today's session-level noise is the biggest accuracy limit.
  • Fallback. If the history service is down, the same model runs on the question alone (graceful degradation, measured above).

4. A brand-new intent in production

  • Detect. Watch the share of needs_review and "other" predictions, plus an out-of-distribution score: the distance of the question's embedding to the nearest class centroid. A sustained rise means something new is arriving.
  • Discover. Cluster the flagged questions weekly (embeddings + HDBSCAN). A reviewer names and defines any coherent new cluster and labels 20–50 examples.
  • Serve meanwhile. Route it to "other" or a human. Optionally add a nearest-neighbour rule on the labelled examples, so the new intent gets routed before retraining.
  • Retrain. Add the class to the head, retrain (about 2 minutes here), rerun grouped CV and calibration, and ship only if the old classes don't regress. The closed label set stays versioned with the model and its calibration.json.

5. Disclosures and limitations

  • Test context. At test time, context comes from the previous test questions (text only, never labels). This assumes the test file is in conversation order, which its adjacent-row similarity supports. Without that order, the model falls back to roughly its no-context quality.
  • Overlap with train. 73 test questions appear verbatim in train, so the test score may be higher than the strict CV estimate.
  • Uncertainty. One training seed per configuration. Differences under about 2 points between variants are within noise.
  • Final model. It is trained on all 1,904 rows with the CV-validated recipe and calibration.
